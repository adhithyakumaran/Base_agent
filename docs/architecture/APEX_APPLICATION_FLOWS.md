# Oracle APEX application flows — QA agent field guide

Enterprise notes for the Endless Aisle / Titan–Tanishq APEX surface and for **any** APEX app the crawler and QA skills will touch. Sourced from Oracle docs, UKOUG APEX UI testing practice, and our UAT discovery.

## 1. What “a flow” means in APEX (vs SPA)

APEX is page- and session-centric, not a single React tree:

| Concept | Reality for automation |
|---|---|
| **Friendly URL** | `/ords/r/{workspace}/{app_alias}/{page_alias}?session=…&cs=…` |
| **Session** | Generated by engine; must ride on clicks or be appended on explicit `goto` |
| **Page** | Full render + regions; many updates via AJAX (`wwv_flow.ajax`) without full reload |
| **Modal / dialog** | Often an **iframe** nested document — must switch context or use frame locators |
| **Popup LOV** | Lives on **parent** page; search → ajax → pick exact match |
| **Interactive Grid (IG)** | DOM rebuilt on refresh/paginate — prefer static IDs / column IDs, not positional CSS |
| **Checksum (`cs`)** | Protects item values in URL; do not invent dialog URLs client-side without server `PREPARE_URL` |

**Crawler rule:** prefer *user clicks* over hand-built URLs. If you must `goto`, always inject the **current** `session` query param.

## 2. Canonical flow shapes the QA agent must recognize

These are **platform** shapes (KB `type: flow_pattern`). Product-specific steps live under Endless Aisle KB flows.

### 2.1 Auth → home land

1. Login page items (username/password) — prefer real keystrokes when CSP blocks `fill`
2. Submit / Login
3. Assert land on home / dashboard (title or known region) — **fail-fast**
4. Capture `session` from URL for the run

Without GT: success = “authenticated session present + home landmark visible”. Business modules list is **candidate** until SME approves.

### 2.2 Module tile → list/search → detail

Typical retail APEX:

`home module` → `search/list page` → optional filters → `detail page` → optional modal (size/customer/variant)

Endless Aisle examples already in KB: standard product browse, item SKU search, find-price, stock visibility, Rivaah trousseau.

### 2.3 Popup LOV / select list (high flake risk)

Industry pattern that works across variants:

1. Click popup trigger  
2. Scope to popup on **parent** page  
3. Clear search, type term  
4. Click search if present  
5. Wait for network containing `/wwv_flow.ajax` (bounded timeout)  
6. Handle “no data found”  
7. Click **exact** match (order matters: “Kev” ≠ first “Kevin”)

Never use unbounded `networkidle` alone as the only wait.

### 2.4 Modal / dialog page

1. Detect dialog open (`iframe.ui-dialog-content`, APEX dialog class, or role=dialog)  
2. Work **inside** frame with dedicated modal budget (e.g. 3s settle, then dismiss/skip)  
3. Close via Cancel / X / Escape — never leave crawl parked on modal  
4. Confirm return to parent before enqueueing more links

### 2.5 Interactive Grid edit

1. Filter to single row when possible  
2. Edit by **column static ID**, not nth-cell when avoidable  
3. After refresh/pagination, re-query locators (DOM was destroyed)  
4. Prefer region static ID `#ig_…` as root

### 2.6 Cross-app jump (multi-app workspace)

Endless Aisle: `ea` (1002), `ea1`, `gc` under `tjdcom`. Treat each app_alias as a crawl partition with shared session when ORDS allows; do not follow external hosts.

## 4. What the QA agent gathers **without** Ground Truth

| Gather | Stored as | Used for |
|---|---|---|
| Pages, aliases, apps | KB `page_map` | Planning, coverage map |
| Components + locators | KB `component` | Stable skills |
| Observed click paths | KB `flow` **candidate** | Replay / probe |
| Screenshots, HAR snippets | evidence refs | Debug / audit |
| ORA / session dead / stuck | rules | Technical FAIL / BLOCKED |
| Module visibility lists | GT **candidates** | SME approval later |

KB never silently becomes PASS/FAIL for business assertions.

## 5. What SME / golden GT adds later (no redesign)

- Approved expected modules, messages, field contracts  
- Allowed empty states (e.g. banner off-hours = PASS)  
- Order / price business rules  

Runtime stays the same: Observation Pipeline compares expected vs actual when `authority=approved`.

## 6. Anti-stuck & performance contract (skills)

Copied into crawler metadata and enforced in code:

- `max_pages` hard stop (default 40)  
- Same URL once per run (unless explicit re-enter skill)  
- Modal timeout then dismiss/skip  
- Navigation timeout 45s  
- Ajax wait bounded (not infinite)  
- Skip external hosts + ORDS separator landings  
- **0 LLM** inside crawl loop  
- No retry because “not PASS yet” — only classified infra retries  

## 7. Useful artifacts for the agent (humans can still help)

Even without full GT, high-value SME/dev inputs:

1. Golden-path browser recording (happy path per role)  
2. Known failure recording (session expiry, ORA page)  
3. Role × store matrix (what BALA vs others see)  
4. Static IDs for critical items (`P6_SKU`, …)  
5. Approval checklist decisions on candidates  

## 8. Enterprise LLM posture (when used)

- Only for ambiguous NL or unclassified observations  
- Behind gateway (fast / reasoning / fallback)  
- Never owns loop control, budgets, or GT comparison  
- Default off in Azure CI and deterministic crawl/sanity
